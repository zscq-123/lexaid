# 学习质量升级与验证记录

依据《LexAid 1.3.0 核心竞争力与改进建议》，本次升级覆盖日常练习、统计、检索、来源展示和学习入口。模拟考试仍保留独立的考试计分规则。

后续复审（11 月 11 日晚至 12 日）发现并修复了隔离绕过、导入题复核遗漏、3 道种子题内容及检索/版本切换问题。**当前可练为 30 题、待复核 25,598 题**；本文件下方的 1,527 / 24,101 是升级初次验证快照，不能作为当前统计。最新证据、修复步骤和验证见 [复审报告](question-audit-2026-11-11.md)。

## 已实现

| 建议 | 代码行为 |
| --- | --- |
| 区分模型评测与学习题 | LawBench / LexEval 原始内容保留；缺少教学复核的基准题不进入日常练习、公共题目检索或关联推荐。新导入的任务指令仅留在来源 metadata，不再写成解析。 |
| 题型、答案、解析和科目检查 | 检查空题、题型、判断题答案、选项文本、重复选项/答案键、参考答案对应关系、任务指令、待判定科目及部分明显科目冲突。疑似问题进入隔离范围，不能按题号绕过抽题限制。 |
| 双人复核基础设施 | `question_quality_review` 保存两个不同审核人、法律依据、关键事实、常见误区、推理及内容指纹。题型、题干、选项、答案、解析或分类改变后，原审核不再有效。 |
| 修复错题和统计 | 各入口统一识别非空实际作答；空多选 `[]` 也算跳过。错题以最近一次实际作答为准；后续跳过既不增加错题，也不抹掉已有错题。统计分别返回实际次数、不同题数、重复次数、答对/错、未评分和跳过。 |
| 历史口径重算 | 新查询直接按历史 `user_answer` 与题型重算，无需覆盖历史行。旧答卷中的空答案展示为跳过。正确率以实际已评分作答次数为分母。覆盖率仅使用当前可练题库，同一题只计一次。 |
| 精确法条查询 | 单个明确法条查询同时匹配法律名称和条号，统一中/阿拉伯数字及“之一”等子条号；支持明确年份版本筛选。此路径不调用模型扩写检索词，不填充其他法律的同条号来源。 |
| 去重和版本 | 相同日期、状态及规范化正文的重复副本合并；不同日期或正文保留。详情提供版本/来源记录切换，公布日、生效日、来源与缺失的失效信息明确显示，均不自动宣称现行有效。 |
| 证据不足 | 精确查询无匹配时直接告知证据不足；AI 提示要求区分收录信息与核验结论，不虚构原文、页码、有效区间。案例和观点页也展示原文定位及出处缺口。 |
| 学习入口 | 用可搜索的内容选择器替代实体 ID；关联组卷只取关联的可练题，不用随机无关题补量。专题由 3 个扩为 6 个，增加事实、观点、假设变式和易错点自查。 |
| 笔记与讨论 | 错题中可直接记笔记，正文支持 `#标签` 并按标签筛选，笔记可返回原题；修复按关联类型筛选笔记。社区空态提供明确标注的讨论题示例与讨论约定，没有伪造用户帖子。 |

## 升级与内容复核

在启动新后端之前，对已有数据库执行 `backend/src/main/resources/question-quality.sql`。脚本可重复执行，仅创建审核表。新数据卷和生产种子包已通过 `docker-compose.yml` 的 `30-question-quality.sql` 引入。

本次已在本机 `lexaid` 数据库执行上述建表脚本；生产数据库未操作。

管理员可使用 `GET /api/admin/question-quality?after=0&limit=50` 读取待复核队列；以最后一项的 `id` 继续分页。返回原因、来源数据集、题目内容和当前 `contentHash`。普通用户不能访问此接口。

内容复核顺序：

1. 对照原始来源，修正题干、答案、选项、解析及 `question_legal_subject` 分类。不要把数据集任务标签当成法学科目。
2. 人工核对法律依据、关键事实、常见误区和简洁推理；需要两名不同审核人。当前版本提供审核存储与管理员队列，审核签署由维护者录入数据库，尚未提供后台在线审稿表单。
3. 内容修订完成后重新读取队列中的 `contentHash`，将审核人及四项审核材料保存至 `question_quality_review`。不要复用修改前的指纹，也不要自动生成审核人或假称完成审核。
4. 基准题只有同时满足基础检查与当前内容的双人审核记录才会重新进入练习。签署不会覆盖空答案、错误选项或任务指令等硬性问题。

历史数据不需要破坏性清洗。应用回退时可保留新增审核表，以免丢失后续人工审核记录。

## 验证

使用隔离数据库 `lexaid_upgrade_20261111_check`，复制当前题库与法条，未在正式用户数据中创建测试作答。

- 后端 `mvn verify`：105 项全部通过，0 跳过；包含真实 MySQL 回归，覆盖历史空答、重复作答、错题恢复、隔离题不能抽取、双人审核指纹失效、选项异常、法条重复副本及版本筛选。
- 数据导入/分类脚本：8 项 Node 测试。
- 前端 `npm run build`。
- `scripts/learning-upgrade-check.mjs`：接口及真实 Chrome 桌面/390px 窄屏验收。包含搜索选材并组卷、统计对账、笔记筛选及原题定位、法条版本切换和六个专题。截图和原始报告写入 `scripts/shots/learning-upgrade/`。
- 统计样例：4 次实际作答 = 3 道不同题 + 1 次重复；答对 2 次、答错 2 次、跳过 3 次，正确率为 50%，当前错题为 1 道。
- 六个固定精确法条问题返回 11 条记录，全部匹配目标法律及条号；两个不存在的名称/条号查询无误补。该小样本只验证精确检索，不能推导开放式问答质量或学习效果。返回不足 5 条时只评估已返回结果，不把缺位算作相关来源。

复跑页面验收前，必须将后端指向隔离数据库并关闭付费模型调用；前端代理到该后端，然后运行：

```bash
LEXAID_CHECK_ISOLATED=yes \
LEXAID_CHECK_API=http://127.0.0.1:8089/api \
LEXAID_CHECK_SITE=http://127.0.0.1:5179 \
LEXAID_CHECK_EXECUTABLE='/Applications/Google Chrome.app/Contents/MacOS/Google Chrome' \
node scripts/learning-upgrade-check.mjs
```

本次没有上线生产，没有调用真实模型评测答案质量，没有完成全库专家复核、权威法律版本补录或文档提出的 30 人 / 7 天学习效果实验。这些属于内容与产品验证，不能由本地代码测试代替。
